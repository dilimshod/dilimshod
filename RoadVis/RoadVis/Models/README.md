# Модели Core ML

Эта папка входит в синхронизированную папку Xcode `RoadVis/`: каждый `*.mlpackage` отсюда Xcode автоматически
компилирует в `<имя>.mlmodelc` внутри приложения. Сам этот README исключён из таргета (membership exception в
`project.pbxproj`), поэтому в приложение не копируется.

## Детектор — четыре пакета (есть в репозитории)

| Пакет | Исходная модель | Вход `image` (Ш×В) | Назначение | Размер |
|---|---|---|---|---|
| `RoadVisDetector.mlpackage` | YOLO11s (`yolo11s.pt`) | 960×544 | альбомный кадр 1920×1080, основной | 19,1 МБ |
| `RoadVisDetectorPortrait.mlpackage` | YOLO11s | 544×960 | портретный кадр 1080×1920, основной | 19,1 МБ |
| `RoadVisDetectorLite.mlpackage` | YOLO11n (`yolo11n.pt`) | 960×544 | альбомный, облегчённый | 5,5 МБ |
| `RoadVisDetectorLitePortrait.mlpackage` | YOLO11n | 544×960 | портретный, облегчённый | 5,5 МБ |

Общее для всех четырёх:

| Параметр | Значение |
|---|---|
| Обучение | COCO (80 классов), веса Ultralytics без дообучения |
| Экспорт | `tools/export_yolo_coreml.py --bundle --force` (Ultralytics 8.4.218, coremltools 9.0, torch 2.7.1 CPU, Linux) |
| Вход | `image` — цветное изображение 16:9 (RGB). Vision растягивает кадр на весь вход (`.scaleFill`, искажение 0,7 %), серых полей нет |
| Доп. входы | `iouThreshold`, `confidenceThreshold` (Double, **необязательные**; по умолчанию 0,45 и 0,25 из слоя NMS) |
| Выходы | `confidence` [N × 80], `coordinates` [N × 4] (x, y, w, h относительно размера изображения) |
| Тип | Pipeline: ML Program (FP16) → NonMaximumSuppression (по классам), spec version 6 |
| Что возвращает Vision | `VNRecognizedObjectObservation` (метка класса COCO + уверенность + нормализованная рамка) |

Почему прямоугольный вход: кадр 1920×1080, вписанный в квадрат 640×640, занимал 640×360 — 44 % входа были серыми
полями, а объекты доходили до сети втрое уменьшенными. Вход 960×544 даёт уменьшение в 2 раза и без полей.

Почему `.scaleFill`: Vision возвращает рамки pipeline‑модели в координатах входа модели; убирает ли он поля
`.scaleFit` — не документировано. Без полей вопрос снимается: рамки верны при любом поведении Vision.

Выбор модели в приложении (`VehicleDetector`): по ориентации кадра; уровень (основная / облегчённая) задаёт
`DetectorQualityGovernor` по измеренному времени вывода и температурному состоянию телефона. Если пакета нет или он
не загрузился, берётся следующий: другой уровень → другая ориентация (кадр растягивается, рамки остаются верными) →
старые имена `yolo26n`, `yolo11n`, `yolov8n`.

Измерено при выборе моделей (BDD100K val, 300 кадров, веса COCO без дообучения; данные США, не Узбекистан):

| Модель и вход | mAP50 | AP малых объектов | Найдено при пороге 0,25: пешеходы / машины / светофоры |
|---|---|---|---|
| YOLO11n, 640 с полями (как было) | 27,5 | 1,7 | 29 % / 40 % / 9 % |
| YOLO11n, 544×960 (облегчённая) | 37,0 | 6,0 | 43 % / 46 % / 14 % |
| YOLO11s, 544×960 (основная) | 47,3 | 8,7 | 48 % / 53 % / 25 % |

Абсолютные числа занижены различием разметки BDD и COCO; надёжно только сравнение строк между собой.

Используемые приложением классы COCO: `car`, `truck`, `bus`, `motorcycle`, `bicycle`, `person`, `traffic light`,
`stop sign` (сопоставление — `VehicleKind(label:)` в RoadVisCore). Остальные метки не сопоставляются и не используются.

Проверено при экспорте (Linux): спецификация каждого пакета прочитана coremltools — вход 960×544 / 544×960, две
стадии pipeline, 80 меток в слое NMS, необязательные пороги; те же веса при том же размере входа в PyTorch дают
правдоподобные рамки на тестовом кадре. **Не проверено**: сами пакеты Core ML на Linux выполнить нельзя (coremltools
предсказывает только на macOS), поэтому компиляция `coremlc`, запуск и скорость на iPhone не проверялись — это
делает Xcode (и CI‑сборка) на macOS и первая поездка. На Mac пакет можно прогнать на фото:
`python tools/export_yolo_coreml.py --check photo.jpg`.

Пересоздать или заменить модели:

```bash
pip install -r tools/requirements.txt
python tools/export_yolo_coreml.py --bundle --force                               # все четыре пакета
python tools/export_yolo_coreml.py --weights yolo26s.pt --imgsz 544 960 --force   # один пакет (ВЫСОТА ШИРИНА)
python tools/export_yolo_coreml.py --bundle --quantize 8 --force                  # ≈ в 2 раза меньше, немного менее точно
```

Своя модель: экспортируйте её дважды (`--imgsz 544 960` → `RoadVisDetector.mlpackage`, `--imgsz 960 544 --out
RoadVis/Models/RoadVisDetectorPortrait.mlpackage`). Метка `rider` (BDD100K) сопоставляется с пешеходом, так что веса,
дообученные на BDD100K (например `dronefreak/bdd100k-yolo11s`), подходят без изменений кода. В репозиторий они не
включены: у них нет класса `stop sign`, вне видеорегистраторных кадров они заметно слабее (COCO‑подвыборка:
mAP50‑95 ≈ 24 против 46), а данные BDD100K — только для некоммерческого использования.

Если ни одного пакета нет, экран камеры показывает пояснение, а скорость и навигатор продолжают работать.

## VehicleMakeClassifier.mlpackage — марки авто (нет в репозитории)

Создаётся скриптом `tools/train_make_classifier.py` (обучение на Stanford Cars, 48 марок, экспорт как
классификатор → Vision возвращает `VNClassificationObservation`). Обучение в репозитории **не запускалось**.
Stanford Cars — только для некоммерческих исследований, и в нём почти нет машин узбекского автопарка
(Cobalt, Nexia, Spark, Damas, Gentra, BYD, Chery…). Для реальной точности нужен собственный размеченный датасет.

## Важно: классы моделей не генерируются

В проекте задано `COREML_CODEGEN_LANGUAGE = None`: Xcode не создаёт Swift‑классы для моделей. Приложение загружает
`RoadVisDetector.mlmodelc` и `VehicleMakeClassifier.mlmodelc` по имени файла из бандла. Поэтому модель можно
заменить файлом с тем же именем без изменений в коде.
